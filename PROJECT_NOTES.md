# Lumiere Premium — Project Notes

Living log of decisions, changes and next steps. **Update this file with every change.**

- **Business:** Lumiere Premium — ladies' garment stitching unit (brands send bulk orders / collections).
- **Stack:** Laravel 12.69 · PHP 8.3 (`php8.3`, the WSL default `php` is 7.4!) · MySQL 8 · Blade + Tailwind 4 + Alpine 3 · Vite
- **URL (local):** http://local.lumiere-app.com (and https, self-signed) → nginx vhost `/etc/nginx/sites-enabled/local.lumiere-app.com`, php8.3-fpm.
- **DB:** `lumiere` (tests use `lumiere_test`). Credentials only in `.env`.
- **First login:** `owner@example.com` (set `OWNER_EMAIL`/`OWNER_PASSWORD` in .env before the first seed) / `ChangeMe@123` (Super Admin) → **change it on /profile**.
- Not a git repo. Nothing is committed.

## Commands (always inside WSL)
```
cd /var/www/html/local.lumiere-app.com
php8.3 artisan migrate            # schema
php8.3 artisan db:seed            # idempotent: roles, permissions, currencies, categories, rate card
php8.3 artisan test               # 15 tests
npm run build                     # frontend (npm run dev for hot reload)
php8.3 artisan schedule:work      # daily due-order notifications (cron: * * * * * php8.3 artisan schedule:run)
```

## Architecture decisions
| Area | Decision | Why |
|---|---|---|
| CRUD | `CrudController` driven by `fields()/columns()/filters()` | one engine for ~20 modules; lists, forms, filters, Excel/PDF export, offline flag are shared |
| Roles | spatie/laravel-permission; permissions `module.action`; `Perms` class is the single list | admin edits role matrix in UI; Super Admin bypass via Gate::before |
| Worker scope | `Tracked` trait + `$ownScoped` → users without `data.all` see only rows they created | "worker can see only their own entries" |
| Worker self-view | `workers.user_id` links a login to a worker; `my.ledger` permission → `/my-ledger` | worker sees own balance sheet only |
| Labour money | balance = earned (work entries + salary entries) − paid (payments + advances), computed live (`Worker::balance`, `Support\Ledger`) | partial payment remainder carries forward automatically; advance = negative balance, adjusted against future earnings |
| Piece rate | rate card on `garment_types.default_rate`, per-worker override in `worker_rates`, **rate snapshotted** on each `work_entries` row | later rate changes never rewrite history |
| Expenses | single `expenses` table, `type` = order/unit/labour/other; order type requires `order_id`; unit type has admin-defined custom fields (JSON `custom`) | one table → simple reports |
| Currency | `amount` + `currency_id` + `exchange_rate` snapshot → `base_amount` (PKR); all reports use base | multi-currency without restating history |
| Offline | service worker (`public/sw.js`) caches visited pages + create forms; `resources/js/offline.js` queues form posts in IndexedDB and replays on reconnect; every submit gets a fresh client `uuid` → server ignores replays | works in the market with no internet |
| OCR | local Tesseract 4.1 (`App\Services\ReceiptOcr`) + regex parser; browser OCR call pre-fills the form; if a receipt arrives without an amount (offline upload) the server OCRs it on save | user chose local OCR; always user-confirmed |
| Notifications | `Notifier::send(event,…)` honours admin matrix (event × in-app/email/WhatsApp); WhatsApp = Cloud API when `WHATSAPP_TOKEN`/`WHATSAPP_PHONE_ID` set, else log-only | admin can enable/disable each |
| i18n | EN + UR (`lang/ur.json`), RTL via `dir` + logical Tailwind classes (`ms-/me-/ps-/start-`) | |
| Audit | every create/update/delete on tracked models → `audit_logs` (`audit.view` permission) | |

## Environment changes made
- Created nginx vhost + self-signed cert `/etc/nginx/ssl/local.lumiere-app.com.*`; added `127.0.0.1 local.lumiere-app.com` to **WSL** `/etc/hosts`.
- Installed `tesseract-ocr` + `tesseract-ocr-urd` (apt).
- **Windows hosts file** (`C:\Windows\System32\drivers\etc\hosts`) must contain `127.0.0.1 local.lumiere-app.com` to open the site from Windows browsers/phone emulation (not editable from WSL).

## Known limits / decisions to revisit
0. **HTTPS certificate (done):** trusted local cert from **mkcert** (installed in WSL, CA at `~/.local/share/mkcert`, **keep `rootCA-key.pem` private**). Cert/key: `/etc/nginx/ssl/local.lumiere-app.com.{crt,key}` (valid to 2029-01-06; covers local.lumiere-app.com, localhost, 127.0.0.1). Root CA imported into the **Windows user trust store** (Chrome/Edge OK; verified with Windows curl). Firefox keeps its own store. A phone on the LAN would need the CA installed on it separately. Renew: `cd /tmp && mkcert -cert-file c.crt -key-file c.key local.lumiere-app.com localhost 127.0.0.1`, copy over the nginx files, `sudo systemctl reload nginx`. Playwright's WSL Chromium does not read this store, so tests there use `--ignore-certificate-errors`.
- **2026-10-07 (round 2)** — Labels: customer form "Customer name"; orders use "Client / Brand". **Branding** in Settings: login logo, dashboard/sidebar logo, favicon (favicon auto-generates 32/180/192/512 px icons used by the dynamic `/manifest.webmanifest`); PNG/JPG/WebP only (SVG rejected on purpose), "remove" restores defaults. `App\Support\Brand`, helper `brand_url()`. Static manifest file removed (now a route). SW cache bumped to v2.
1. Browser-tested with Playwright (mobile 390×844 and desktop 1366×800): login, customer create, offline queue + sync, dashboard, lists, expense form. Not yet exercised in browser: invoice form, roles matrix, receipt OCR upload, Urdu RTL layout.
2. Offline: a record saved offline that fails server validation is marked *Rejected* on **/sync** (discard/retry). Edits and deletes are online-only. Pages never visited/precached are unavailable offline (quick-add forms and dashboard are precached after login).
3. PDF Urdu: DomPDF has no Urdu shaping — Urdu text in PDFs will be broken; English PDFs are fine. Excel exports are fine.
4. OCR accuracy depends on screenshot quality; payee detection is weakest. Values are always editable.
5. Balance sheet = assets − liabilities (net worth); inventory stock is not valued (purchases are expensed). Record machine/furniture purchases in **Assets** *and* as a **Unit expense** (so cash drops); P&L then counts it as an expense (cash view).
6. Order has a single quantity/rate (no per-style/size breakdown yet).
7. SMS channel not built (deferred). WhatsApp needs a provider account.
8. Seeded USD/AED/SAR rates are placeholders — update on the Currencies page.
9. Default garment rates are 0 — set them on **Garments & rate card**.
